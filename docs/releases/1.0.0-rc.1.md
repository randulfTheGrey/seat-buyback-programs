# Buyback Programs 1.0.0-rc.1

`1.0.0-rc.1` is the first public release candidate of Buyback Programs for SeAT
5. It is intended for third-party installation and validation before stable
`1.0.0`; operators should back up data, review the Laravel 10 compatibility
policy, and test in a non-production SeAT environment first.

## Highlights

- Multiple independently configurable buyback Programs.
- Deterministic sparse GROUP/TYPE rules with compression-aware GROUP policies.
- Logical BUY, SELL, and SPLIT references through `seat-prices-core` only.
- Exact decimal pricing and additive basis-point modifiers.
- Transient appraisals and immutable payable-only Quotes.
- Separate requester and manager fulfillment Request lifecycle.
- Independent `buyback.request`, `buyback.manage`, and `buyback.admin`
  permissions.
- CCP SDE compression projection with scheduled, last-known-good synchronization.

## Requirements

SeAT 5, PHP 8.2+, Composer 2, Laravel 10.48.29+, current compatible SeAT 5
components, and `seat-prices-core` 1.0.1+. Web, worker/Horizon, scheduler, shared
cache, and database services must follow the normal SeAT deployment model.

## Installation

After the GitHub tag and Packagist package are published:

```bash
composer require randulfthegrey/seat-buyback-programs:^1.0@RC
php artisan migrate --force
php artisan db:seed --class='Seat\\Services\\Database\\Seeders\\PluginDatabaseSeeder' --force
php artisan buyback:sync-compression-data
```

Read [installation.md](../installation.md) before enabling a Program.

## Architecture characteristics

All persistence is plugin-owned. `seat-prices-core` is the exclusive pricing
boundary. CCP SDE data is the exclusive compression authority. Appraisals are
short lived, Quotes are immutable financial evidence, and Requests are a
separate fulfillment lifecycle. No permission implies another.

## Known limitations

The RC contains no automatic EVE contract reconciliation, direct market-provider
client, partial fulfillment, manual price override, payout/accounting ledger,
Program-specific eligibility, notification/Discord subsystem, category rules,
or arbitrary expression engine. Laravel 10 is end-of-life upstream but remains
the SeAT 5 requirement; see ADR 0013.

## RC expectations and feedback

Pre-stable migrations and APIs may still evolve when release-blocking defects
are discovered. Stable `1.0.0` follows successful public installation,
Packagist, upgrade, and end-to-end validation. Breaking changes after stable
release require the appropriate SemVer major release.

During RC validation, private GitLab remains development, issue, and CI
authority. GitHub starts with a clean release-only history for public source,
releases, and Packagist integration. After stable `1.0.0` is validated and the
recorded cutover is complete, GitHub becomes authoritative for development and
public contribution.
